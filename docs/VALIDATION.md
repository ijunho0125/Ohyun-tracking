## 패드 그림 저장 → 다른 컴퓨터의 디노 런 자동 적용 (2026-10-23)

이번 변경에서는 `/draw` 그리기 화면에 한해 패드·터치 입력을 추가했습니다. 게임 화면의 PC 전용 구성은 유지합니다. 사용자가 이미지 저장을 누르면 Node 서버가 원본과 PNG·선택 정보를 보관한 뒤 SSE로 연결된 게임에 전달합니다. 다운로드나 별도의 이미지 사용 버튼은 없으며 저장 동작은 게임을 시작하지 않습니다.

- `tests/character-api.test.ts`: 잘못된 메타데이터·다른 출처 쓰기 차단, 동시 저장 시 데이터 보존, 원본/PNG 읽기, 저장과 선택의 동시 처리, 실시간 알림, 서버 재시작 후 그림·선택 복원, 선택된 그림 삭제를 검사했습니다.

- 빈 그림 저장 방지, 투명 PNG와 자동 여백 자르기, 파일 다운로드 0회, 연결 끊김 뒤 최신 선택 수신, 새로고침 후 선택 복원, 저장 실패 시 기존 캐릭터와 패드 그림 유지도 통과했습니다. 1024×768, 768×1024, 390×844에서 캔버스 비율과 가로 넘침을 확인했습니다.

## 빠른 추적과 점프 시작 감지 (2026-10-23)

[hop-hop-jump-detection의 main.py](https://github.com/ijunho0125/hop-hop-jump-detection/blob/00a2548ce91ab59178c42b54725838a70c2fbdaf/main.py)를 검토했습니다. 몸 중심의 상승 속도, 무릎 각도의 숙이기 보조, 중복 점프 방지, 최신 프레임만 처리하는 원리를 브라우저 구현에 적용했습니다. Python·OpenCV·PyAutoGUI 코드를 가져오거나 실행하지 않고 현재의 MediaPipe Worker와 게임 명령을 유지합니다.

- 기본 최대 인식 빈도는 30Hz, 카메라는 가능한 경우 60fps를 요청합니다. 프레임은 한 장만 처리하며, 처리 중 새 프레임은 대기열에 쌓지 않습니다. 카메라 프레임 콜백과 RAF 대체 경로를 함께 사용해, 숨겨진 영상 요소의 콜백이 중단되어도 추적을 이어갑니다. 시간표를 누적해 30fps 카메라에서 20Hz 설정이 15Hz로 떨어지던 반올림 손실을 줄였습니다.
- 큰 영상은 추론 전에 가로 640px로 줄이고 실제 원본 크기를 결과에 보존합니다. 관절의 정규화 좌표와 영상 표시의 대응을 유지합니다.
- 실제 하드웨어 WebGL2가 있으면 GPU 모델을 사용합니다. 소프트웨어 WebGL은 CPU로 처리하며 GPU 초기화·추론 오류도 CPU로 복구합니다. 모델 로드와 첫 추론 도착을 구분해 GPU의 초기 준비를 인식 소실로 오해해 재개가 중단되지 않게 합니다. API 근거는 설치된 0.10.32의 `vision.d.ts`와 [MediaPipe 웹 설정 문서](https://developers.google.com/edge/mediapipe/solutions/setup_web)입니다.
- 어깨·골반의 상승이 이어지는 동안 몸 중심의 속도와 최소 상승량이 확인되면 기존 높이 임계값에 닿기 전에 점프를 전달합니다. 어깨만 움직임·한 프레임 튐·중립 복귀 전 반복 점프는 계속 차단합니다. 보이는 무릎이 접히고 몸도 내려가면 숙이기를 일찍 인식하며, 다리가 화면 밖이면 기존 상체 기준을 사용합니다.

단위 검사에서 프레임 처리 중복 방지, 20/30Hz 일정, GPU 오류 복구, 빠른 점프와 무릎 보조를 검사했습니다. `npm.cmd run test:tracking-speed`는 공식 손 사진의 Canvas 스트림과 실제 Worker·모델로 지속 추적을 측정합니다. [로컬 측정 결과](tracking-speed-results.json)의 30Hz 설정에서는 GPU 경로가 선택되어 실제 약 14.3회/초, 프레임 처리 지연 중앙값 약 54ms였습니다. 이는 이 실행 환경의 사진 스트림 측정이며, 실제 웹캠에서 30fps나 같은 지연을 보장하는 값이 아닙니다. 첫 커널 준비는 측정 구간에서 제외합니다.

최종 확인: 단위 검사 14개 파일·109개 통과, 타입·빌드 통과, 디노 모션 흐름(1.8초 로딩 + 1.6초 첫 추론 지연 포함) 통과, 실제 손 사진 인식·관절 표시 통과. `npm.cmd run test:vision`의 실제 손/몸/동시 모델 로드·빈 영상 추론·오류 복구 등 11개 항목도 통과했습니다. 전체 화면 회귀 검사는 동시에 변경된 그림 편집 화면의 기존 버튼 선택자에서 실패했으므로, 전체 UI 검사 통과로 보고하지 않습니다.

## 최신: 테트리스 점프 회전 · 앉기 소프트 드롭 (2026-10-23)

테트리스 모션 회전을 고개 끄덕이기에서 점프로 변경했습니다. 앉은 자세는 소프트 드롭을 유지하고 일어서면 해제합니다. 왼손 주먹은 왼쪽, 오른손 주먹은 오른쪽 이동이며 기존 양손 주먹 즉시 낙하도 유지합니다. 손 입력의 기본 해제 명령이 몸 입력의 소프트 드롭을 끊지 않도록 두 입력을 합칩니다. 디노의 앉은 모드 설정과 독립적으로 몸 동작을 사용합니다.

모션 진입·다시 준비 시 양손과 어깨·골반을 보여 기준 자세를 보정합니다. 점프는 중립 복귀 전 반복 회전하지 않으며, 손이나 몸 추적 소실 시 소프트 드롭과 동작 준비를 초기화합니다. 로비·설정·연습 안내와 카메라 관절 표시도 손·몸 조작에 맞췄습니다.

## 모션 점프 인식과 디노 장애물 간격 (2026-10-23)

게임에 먼저 들어가 카메라를 연결하면, 관절점은 보이지만 입력 모드는 키보드로 남아 모션을 무시하는 문제를 재현하고 수정했습니다. 준비 화면에서 카메라 연결이 완료되면 모션으로 전환하며, 사용자가 직접 고른 키보드 모드는 유지합니다. 일시정지 화면에는 모션 전환·자세 보정 버튼을 추가하고, 키보드 입력 중임을 하단에 표시합니다.

몸이 올라간 뒤 정점에서 멈추는 점프를 놓치지 않도록, 상승 시작과 올라간 자세의 연속 확인을 분리했습니다. 몸 입력은 커서보다 빠르게 반응하며 프레임 간격에 따라 보정합니다. 어깨와 골반의 상승을 함께 확인하고, 중립 복귀 전 반복 점프·한 프레임의 흔들림·추론 지연 뒤 오래된 동작의 완성을 막습니다. 손 올리기에는 visibility와 presence를 모두 통과한 손목만 사용합니다. 보정 중의 정상 인식 시각을 갱신하지 않아 보정 완료 직후 바로 일시정지될 수 있던 문제와, 모델 로딩 시간을 추적 소실로 잘못 판단해 재개가 중단되는 문제도 수정했습니다.

디노 모션 모드는 연속 장애물 묶음 없이 하나씩 생성합니다. 기본 속도 설정은 260, 장애물 최소 간격은 3.2초이며 최대 5초까지 늘릴 수 있습니다. 이동 속도는 완만하게 증가합니다. 이후 속도 조정으로 모션 기본 달리기를 3.9에서 6.5px/프레임으로, 상한을 6에서 10px/프레임으로 높였습니다. 키보드 기본 달리기도 약 1.33배 빨라졌으며 달리는 발의 애니메이션도 속도에 맞춥니다. 장애물 사이에는 새 최고 속도와 1.3배 가속 효과를 고려한 이동 거리를 확보하므로 실제 간격은 설정한 최솟값보다 길 수 있습니다. 앉은 모드에서는 점프로 넘는 장애물만 나오며 연습에도 숙이기를 요구하지 않습니다. 이전 기본 설정은 새 기본값으로 이전하고, 별도로 조절한 값은 유지합니다.

시작 2초·재개 1초 동안 보호하며, 모션 입력으로 점프한 뒤 450ms·숙이기 시작 뒤 300ms·착지 뒤 180ms 동안 판정에 여유를 줍니다. 모션 충돌은 약 140ms 동안 유예해 실제 점프·숙이기가 뒤늦게 도착해도 구제합니다. 구제한 장애물은 화면에 남아 자연스럽게 지나가며 가속 아이템의 충돌 보너스를 지급하지 않습니다. 보호 시간은 일시정지 중 흐르지 않고, 공중 점프 재입력이나 숙인 자세 유지로 계속 갱신되지 않습니다. 보호가 끝난 뒤 새 장애물에 부딪히면 정상적으로 종료하며, 재시작·종료 때 보정 상태를 비웁니다.

- 속도·판정 보정 검증: `npm.cmd test` 13개 파일·103개 테스트와 `npm.cmd run build` 통과. `test:dino-motion`의 실제 게임 문서에서 서기·앉기 모두 시작·점프·숙이기·착지·재개 보호, 늦은 입력 구제, 보호 만료 후 충돌 종료, 장애물 표시 유지, 가속 아이템 보너스, 초기화·종료를 확인했습니다. 아래의 모의 카메라 흐름 검사와 함께 실행합니다.

- `npm.cmd test`: 11개 파일, 79개 테스트 통과. 기본 보정 계수의 10/20/30Hz 정점 점프, 작은 흔들림·어깨만 움직임·가려진 손목·추론 중단, 설정 이전을 포함합니다.

## 코드 정리와 로딩 최적화 (이전 기록)

사용하지 않는 이전 디노·테트리스 엔진과 관련 상수·import를 제거했습니다. 원본 HTML 게임은 유지했으며, 이전 엔진을 검사하던 단위 테스트는 실제 화면이 사용하는 SourceGame 어댑터 검사로 교체했습니다. 게임 설명을 별도 모듈로 분리하고 게임·그림 편집·튜토리얼·체험관을 필요할 때 불러옵니다.

- 초기 JavaScript: 429.07KB → 273.27KB, 약 36% 감소. gzip 기준 127.96KB → 87.28KB. 보조 화면 파일은 별도로 로드됩니다.

## 테트리스 주먹 조작 변경 (이전 기록)

왼손만 주먹이면 왼쪽, 오른손만 주먹이면 오른쪽, 양손 모두 주먹이면 빠른 낙하로 변경했습니다. 실제 손의 좌우를 사용하며 기존 `swapHands` 저장값은 무시합니다. 시작·추적 복구 뒤에는 양손을 펴서 준비합니다. 한 손 주먹은 확인 후 350ms 대기, 이후 150ms 간격으로 이동을 반복합니다. 양손 주먹과 부분적으로 접는 중인 손은 좌우 이동을 즉시 중단하고, 양손 주먹 확인이 끝나면 빠른 낙하만 활성화합니다. 한 손을 펴거나 추적이 끊기면 낙하를 해제합니다. 회전은 양손을 편 채 오른손을 기울일 때만 가능합니다.

로비·게임·설정 안내를 갱신했고 연습 체크에 빠른 낙하를 추가했습니다. 단위 검사는 52개이며 단독 주먹 방향, 화면상의 손 위치와 무관한 좌우, 반복 간격, 시간·프레임 확인, 양손 우선 처리, 낙하 해제, 추적 소실, 회전 충돌 방지를 포함합니다. `test:motion`은 합성 관절 입력을 실제 원본 테트리스에 전달해 이동 방향과 낙하 상태를 확인합니다.

## 오른손 인식 오류 수정

설치된 MediaPipe 0.10.32의 Hand Landmarker 결과에는 관절별 `visibility`가 기본값 0으로 포함됩니다. 기존 코드는 이를 Pose Landmarker의 실제 가시성 점수처럼 검사해, 모델이 검출한 오른손을 커서·게임 입력·관절 표시에서 모두 제외했습니다. 이전 모의 입력에 이 필드가 없어서 기존 검사는 이 오류를 놓쳤습니다.

손 좌표에서는 해당 기본값을 실패로 사용하지 않도록 수정했습니다. Worker는 손의 x·y·z만 전달하고, 화면 표시도 손과 몸의 가시성 기준을 분리했습니다. 몸의 실제 visibility/presence 검사는 유지합니다. 카메라 아래에는 감지된 손과 설정한 조작 손을 함께 표시합니다. 좌우 손을 임의로 뒤집거나 다른 손으로 자동 대체하지 않습니다.

공식 `right_hands.jpg` 사진을 실제 MediaPipe 모델에 넣어 수정 전후를 비교했습니다. 오른손 분류 확률 약 0.952·0.971인 두 손 모두 `visibility: 0`이었고, 수정 전의 `unknown` 판정이 수정 후 `open`으로 바뀌었습니다. 이 수치는 사진 속 손의 좌우 분류 확률이며 실시간 인식 정확도가 아닙니다.

- `npm.cmd run test:right-hand` 통과: 실제 모델 원본 출력, 실제 Worker 출력, 손 사진 Canvas 스트림을 넣은 앱의 오른손 커서·관절 표시·감지 상태를 확인했습니다. 카메라 영상원만 사진 스트림으로 바꾸고 모델과 Worker는 모의 구현하지 않았습니다.
- [수정 전 결과](right-hand-before.json) / [수정 후 결과](right-hand-check-results.json) / [실제 모델 화면](screenshots/pc-right-hand-real-model.png).
- 모의 손 좌표도 실제 SDK와 같이 `visibility: 0`을 포함하도록 바꿨습니다. 손과 몸의 가시성 분리 회귀 검사를 추가했습니다.
- 이미지 출처는 [테스트 자산 기록](../tests/fixtures/SOURCES.md)에 정리했습니다. 모델의 손 결과 구성은 [공식 문서](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)를 참고했습니다. 기본값 처리는 설치된 `node_modules/@mediapipe/tasks-vision/vision_bundle.mjs`에서 직접 확인했습니다.

실제 사용자의 웹캠, 조명, 거리에서의 성공률은 별도 확인이 필요합니다.

단위 검사는 손바닥 중심과 반전·화면 매핑, 여러 손가락의 굽힘, 작은 손·잘림·낮은 신뢰도 거부, 주먹 유지 시간과 연속 프레임, 완전히 편 뒤 재선택, 대상 고정, 화면 전환·소실 초기화, 검지 굽힘·엄지와 검지 접촉의 비선택, 양손 역할과 테트리스 회전·빠른 낙하·입력 해제, 자세 보정·점프·기울기, 세 게임의 생명주기·물리·충돌, 카메라 요청 취소·Worker 정리·재시도, 이미지 배경 제거를 확인합니다.

## PC 화면과 실제 UI 동작

1280·1440·1920px 너비에서 사이드 내비게이션 부재, 가로 넘침 부재, 큰 카드 크기, 원본과 일치하는 로고 비율을 확인했습니다. 원본 로고와 분리한 두 로고를 직접 열어 글자와 호랑이가 잘리지 않는지 확인했습니다. 버건디·크림·주황색과 실제 사용 토큰은 [DESIGN.md](../DESIGN.md)에 정리했습니다.

실제 브라우저에서 다음을 확인했습니다.

- 설정·도움말 중앙 모달, 키보드 포커스 유지, Esc 닫기.
- 디노: 점프·숙이기 연습, 카운트다운·점수·종료·재시작·일시정지·재개·로비 복귀.
- 테트리스: 키보드 이동·회전·낙하, 점수·종료·재시작·일시정지.
- 밸런스 볼: 키보드 좌우 기울기, 카운트다운·시간 점수·종료·재시작·일시정지.
- 실제 PNG 파일 선택, Canvas 미리보기와 점프 변형, IndexedDB 저장, 저장한 캐릭터의 디노 선택.
- 손 튜토리얼이 시간 경과·마우스 입력으로 성공하지 않는 것, 명시적 건너뛰기와 직접 키보드 조작 후 연습 완료.
- 기술 체험관 손/몸 전환·좌표 대기 상태·기준 자세 보정 버튼·그림 비율 변경.
- 카메라 확대와 관절 표시 켜기·끄기.

이미지를 새로 등록하거나 잘라내기·배경 제거를 변경할 때 기존 처리 Blob을 비웁니다. 새 이미지 처리와 미리보기 디코딩이 끝나야 저장할 수 있도록 보강했습니다. 이전 비동기 작업의 결과가 새 그림을 덮지 않도록 작업 버전을 확인합니다.

## 모의 카메라·관절 입력

테스트 프로세스에서 `getUserMedia`와 Worker만 모의 구현합니다. 영상은 1280 × 720 Canvas 스트림, 관절은 명시적으로 만든 손 좌표입니다. 앱의 실제 커서·선택 상태 머신·튜토리얼·관절 그리기·게임 전환 코드를 그대로 실행합니다. 제품 코드에 테스트 전용 전역 API는 없습니다.

- 손바닥 커서와 카드의 머무르기 표시가 작동합니다. 검지만 굽히거나 엄지와 검지를 맞대도 클릭하지 않습니다.
- 손을 접는 동안 커서 위치와 최초 선택 대상이 유지됩니다. 주먹을 다른 카드 위치로 옮겨도 처음 대상을 선택합니다.
- 주먹 한 번에 클릭 한 번, 유지 중 추가 클릭 없음, 다음 화면의 버튼 자동 실행 없음.
- 손이 사라지면 준비를 초기화합니다. 주먹 상태로 다시 나타나도 클릭하지 않습니다. 지정하지 않은 손이 나타나도 커서를 넘기지 않습니다.
- 영상과 관절 Canvas의 16:9 크기·위치·반전이 같습니다. 실제 관절 위치의 Canvas 픽셀을 확인하고 확대·화면 배율 변경 후 두 경계를 비교했습니다. 표시를 끄면 Canvas의 알파가 모두 0입니다.
- 호랑이 튜토리얼은 열린 손 → 커서의 실제 이동과 목표 도착 → 모션 클릭 → 손 펴기 확인을 거쳐 진행합니다. 마우스 클릭이나 시간 경과는 해당 단계를 완료하지 않습니다.
- 테트리스 연습 중 주먹은 게임 입력으로만 사용됩니다. 사이트 버튼은 클릭되지 않고 메뉴 커서도 숨겨집니다.
- 필요한 손 소실 시 유지 입력을 해제하고, 중단이 이어지면 일시정지합니다. 오래된 관절과 커서도 사라집니다.
- 게임 12회 전환 후 카메라 스트림 1개, 최대/현재 Worker 1개, 대기 RAF 2개 이하, 게임별 이벤트 구독 1개씩을 확인했습니다. 문서 visibility 구독은 앱과 게임에 각각 1개로 총 2개입니다. Playwright 자체의 포인터 이벤트 검사기는 앱 구독 집계에서 제외했습니다.

## 실제 모델의 합성 프레임 검사

`/tests/worker-smoke.html`에서 모의 Worker를 사용하지 않고 아래 9개 항목을 통과했습니다.

1. Hand Landmarker와 설치된 MediaPipe 0.10.32 WASM 로드.
2. 실제 Worker에서 빈 합성 영상 추론, 손 기준점 0개.
3. Pose Landmarker Lite와 같은 WASM 로드.
4. 실제 Worker에서 빈 합성 영상 추론, 몸 기준점 0개.
5. 잘못된 모델 경로 오류 보고.
6. 새 Worker에서 모델 재시도 성공.
7. 실제 Canvas 단색 배경 제거와 그림 픽셀 보존.
8. 실제 Canvas 잘라내기 결과 40 × 80.
9. IndexedDB 원본·처리 Blob 저장·조회·검사 데이터 삭제.

처리 시간은 결과 JSON에 해당 프레임의 측정값으로만 기록합니다. 빈 영상 한 장의 처리 시간을 실제 사람의 지속 FPS·입력 지연·인식 정확도로 보고하지 않습니다.

## 남은 실기기 확인

- 실제 사람의 손·몸, 조명·거리·가림, 카메라별 좌우 손 분류, 주먹 임계값과 커서 감각은 시험하지 않았습니다. 모의 좌표는 모델의 실제 오인식 가능성을 검증하지 않습니다. 실기기에서 유지 시간·연속 프레임·보정을 조정해야 할 수 있습니다.
- 실제 카메라 권한 허용·거부, 물리 장치 분리·재선택은 실기기에서 확인해야 합니다. 해당 오류와 자원 정리 코드는 서비스 모의 테스트로 검사했습니다.
- PNG는 실제 브라우저 업로드로 검증했습니다. 다양한 사용자 그림의 여백·비율과 JPG·WebP 파일은 추가 현장 확인이 필요합니다.
- 장시간 실제 카메라 세션의 성능·배터리·메모리와 운영 HTTPS 호스트의 CSP·WASM MIME 설정은 검증하지 않았습니다. 자동 배포는 하지 않았습니다.
- 디노 점프는 어깨·골반의 위치 변화 추정이고 밸런스 입력은 상체 기울기입니다. 실제 점프 높이나 무게중심의 정밀 측정값은 아닙니다.
