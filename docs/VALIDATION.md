- 초기 JavaScript: 429.07KB → 273.27KB, 약 36% 감소. gzip 기준 127.96KB → 87.28KB. 보조 화면 파일은 별도로 로드됩니다.
- 인식 Worker: 195,574바이트 → 136,352바이트, 약 30% 감소. 실제 모델 로드·추론 검사도 통과했습니다.
- 카메라 상태 확인용 반복 타이머를 만료 시점의 단일 타이머로 바꿨습니다. 모드 전환 뒤 이전 Worker나 이미지 요청의 오류가 새 연결을 중단하지 않도록 수정했습니다.

## 테트리스 주먹 조작 변경 (이전 기록)

왼손만 주먹이면 왼쪽, 오른손만 주먹이면 오른쪽, 양손 모두 주먹이면 빠른 낙하로 변경했습니다. 실제 손의 좌우를 사용하며 기존 `swapHands` 저장값은 무시합니다. 시작·추적 복구 뒤에는 양손을 펴서 준비합니다. 한 손 주먹은 확인 후 350ms 대기, 이후 150ms 간격으로 이동을 반복합니다. 양손 주먹과 부분적으로 접는 중인 손은 좌우 이동을 즉시 중단하고, 양손 주먹 확인이 끝나면 빠른 낙하만 활성화합니다. 한 손을 펴거나 추적이 끊기면 낙하를 해제합니다. 회전은 양손을 편 채 오른손을 기울일 때만 가능합니다.

로비·게임·설정 안내를 갱신했고 연습 체크에 빠른 낙하를 추가했습니다. 단위 검사는 52개이며 단독 주먹 방향, 화면상의 손 위치와 무관한 좌우, 반복 간격, 시간·프레임 확인, 양손 우선 처리, 낙하 해제, 추적 소실, 회전 충돌 방지를 포함합니다. `test:motion`은 합성 관절 입력을 실제 원본 테트리스에 전달해 이동 방향과 낙하 상태를 확인합니다.

## 오른손 인식 오류 수정

설치된 MediaPipe 0.10.32의 Hand Landmarker 결과에는 관절별 `visibility`가 기본값 0으로 포함됩니다. 기존 코드는 이를 Pose Landmarker의 실제 가시성 점수처럼 검사해, 모델이 검출한 오른손을 커서·게임 입력·관절 표시에서 모두 제외했습니다. 이전 모의 입력에 이 필드가 없어서 기존 검사는 이 오류를 놓쳤습니다.

손 좌표에서는 해당 기본값을 실패로 사용하지 않도록 수정했습니다. Worker는 손의 x·y·z만 전달하고, 화면 표시도 손과 몸의 가시성 기준을 분리했습니다. 몸의 실제 visibility/presence 검사는 유지합니다. 카메라 아래에는 감지된 손과 설정한 조작 손을 함께 표시합니다. 좌우 손을 임의로 뒤집거나 다른 손으로 자동 대체하지 않습니다.

공식 `right_hands.jpg` 사진을 실제 MediaPipe 모델에 넣어 수정 전후를 비교했습니다. 오른손 분류 확률 약 0.952·0.971인 두 손 모두 `visibility: 0`이었고, 수정 전의 `unknown` 판정이 수정 후 `open`으로 바뀌었습니다. 이 수치는 사진 속 손의 좌우 분류 확률이며 실시간 인식 정확도가 아닙니다.

- `npm.cmd run test:right-hand` 통과: 실제 모델 원본 출력, 실제 Worker 출력, 손 사진 Canvas 스트림을 넣은 앱의 오른손 커서·관절 표시·감지 상태를 확인했습니다. 카메라 영상원만 사진 스트림으로 바꾸고 모델과 Worker는 모의 구현하지 않았습니다.
- [수정 전 결과](right-hand-before.json) / [수정 후 결과](right-hand-check-results.json) / [실제 모델 화면](screenshots/pc-right-hand-real-model.png).
- 모의 손 좌표도 실제 SDK와 같이 `visibility: 0`을 포함하도록 바꿨습니다. 손과 몸의 가시성 분리 회귀 검사를 추가했습니다.
- 이미지 출처는 [테스트 자산 기록](../tests/fixtures/SOURCES.md)에 정리했습니다. 모델의 손 결과 구성은 [공식 문서](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)를 참고했습니다. 기본값 처리는 설치된 `node_modules/@mediapipe/tasks-vision/vision_bundle.mjs`에서 직접 확인했습니다.

실제 사용자의 웹캠, 조명, 거리에서의 성공률은 별도 확인이 필요합니다.

## PC 화면과 실제 UI 동작

1280·1440·1920px 너비에서 사이드 내비게이션 부재, 가로 넘침 부재, 큰 카드 크기, 원본과 일치하는 로고 비율을 확인했습니다. 원본 로고와 분리한 두 로고를 직접 열어 글자와 호랑이가 잘리지 않는지 확인했습니다. 버건디·크림·주황색과 실제 사용 토큰은 [DESIGN.md](../DESIGN.md)에 정리했습니다.

실제 브라우저에서 다음을 확인했습니다.

- 설정·도움말 중앙 모달, 키보드 포커스 유지, Esc 닫기.
- 디노: 점프·숙이기 연습, 카운트다운·점수·종료·재시작·일시정지·재개·로비 복귀.
- 테트리스: 키보드 이동·회전·낙하, 점수·종료·재시작·일시정지.
- 밸런스 볼: 키보드 좌우 기울기, 카운트다운·시간 점수·종료·재시작·일시정지.
- 실제 PNG 파일 선택, Canvas 미리보기와 점프 변형, IndexedDB 저장, 저장한 캐릭터의 디노 선택.

- 기술 체험관 손/몸 전환·좌표 대기 상태·기준 자세 보정 버튼·그림 비율 변경.

## 모의 카메라·관절 입력

테스트 프로세스에서 `getUserMedia`와 Worker만 모의 구현합니다. 영상은 1280 × 720 Canvas 스트림, 관절은 명시적으로 만든 손 좌표입니다. 앱의 실제 커서·선택 상태 머신·튜토리얼·관절 그리기·게임 전환 코드를 그대로 실행합니다. 제품 코드에 테스트 전용 전역 API는 없습니다.

- 손바닥 커서와 카드의 머무르기 표시가 작동합니다. 검지만 굽히거나 엄지와 검지를 맞대도 클릭하지 않습니다.
- 손을 접는 동안 커서 위치와 최초 선택 대상이 유지됩니다. 주먹을 다른 카드 위치로 옮겨도 처음 대상을 선택합니다.
- 주먹 한 번에 클릭 한 번, 유지 중 추가 클릭 없음, 다음 화면의 버튼 자동 실행 없음.
- 손이 사라지면 준비를 초기화합니다. 주먹 상태로 다시 나타나도 클릭하지 않습니다. 지정하지 않은 손이 나타나도 커서를 넘기지 않습니다.
- 영상과 관절 Canvas의 16:9 크기·위치·반전이 같습니다. 실제 관절 위치의 Canvas 픽셀을 확인하고 확대·화면 배율 변경 후 두 경계를 비교했습니다. 표시를 끄면 Canvas의 알파가 모두 0입니다.
- 호랑이 튜토리얼은 열린 손 → 커서의 실제 이동과 목표 도착 → 모션 클릭 → 손 펴기 확인을 거쳐 진행합니다. 마우스 클릭이나 시간 경과는 해당 단계를 완료하지 않습니다.
- 테트리스 연습 중 주먹은 게임 입력으로만 사용됩니다. 사이트 버튼은 클릭되지 않고 메뉴 커서도 숨겨집니다.
- 필요한 손 소실 시 유지 입력을 해제하고, 중단이 이어지면 일시정지합니다. 오래된 관절과 커서도 사라집니다.
- 게임 12회 전환 후 카메라 스트림 1개, 최대/현재 Worker 1개, 대기 RAF 2개 이하, 게임별 이벤트 구독 1개씩을 확인했습니다. 문서 visibility 구독은 앱과 게임에 각각 1개로 총 2개입니다. Playwright 자체의 포인터 이벤트 검사기는 앱 구독 집계에서 제외했습니다.

## 실제 모델의 합성 프레임 검사

`/tests/worker-smoke.html`에서 모의 Worker를 사용하지 않고 아래 9개 항목을 통과했습니다.

1. Hand Landmarker와 설치된 MediaPipe 0.10.32 WASM 로드.
2. 실제 Worker에서 빈 합성 영상 추론, 손 기준점 0개.
3. Pose Landmarker Lite와 같은 WASM 로드.
4. 실제 Worker에서 빈 합성 영상 추론, 몸 기준점 0개.
5. 잘못된 모델 경로 오류 보고.
6. 새 Worker에서 모델 재시도 성공.
7. 실제 Canvas 단색 배경 제거와 그림 픽셀 보존.
8. 실제 Canvas 잘라내기 결과 40 × 80.
9. IndexedDB 원본·처리 Blob 저장·조회·검사 데이터 삭제.

처리 시간은 결과 JSON에 해당 프레임의 측정값으로만 기록합니다. 빈 영상 한 장의 처리 시간을 실제 사람의 지속 FPS·입력 지연·인식 정확도로 보고하지 않습니다.

## 남은 실기기 확인

- 실제 사람의 손·몸, 조명·거리·가림, 카메라별 좌우 손 분류, 주먹 임계값과 커서 감각은 시험하지 않았습니다. 모의 좌표는 모델의 실제 오인식 가능성을 검증하지 않습니다. 실기기에서 유지 시간·연속 프레임·보정을 조정해야 할 수 있습니다.
- 실제 카메라 권한 허용·거부, 물리 장치 분리·재선택은 실기기에서 확인해야 합니다. 해당 오류와 자원 정리 코드는 서비스 모의 테스트로 검사했습니다.
- PNG는 실제 브라우저 업로드로 검증했습니다. 다양한 사용자 그림의 여백·비율과 JPG·WebP 파일은 추가 현장 확인이 필요합니다.
- 장시간 실제 카메라 세션의 성능·배터리·메모리와 운영 HTTPS 호스트의 CSP·WASM MIME 설정은 검증하지 않았습니다. 자동 배포는 하지 않았습니다.
- 디노 점프는 어깨·골반의 위치 변화 추정이고 밸런스 입력은 상체 기울기입니다. 실제 점프 높이나 무게중심의 정밀 측정값은 아닙니다.
